# Replay selected by measured forgetting

Freeze before new GPU outcomes. Use the three saved small-buffer trajectories from `buffer_stability/` (seeds 17,29,43). Before checkpoint: small-buffer wave one; affected checkpoint: small-buffer wave two. This is a recovery comparison on already observed failures, not an independent replication, newly held-out cohort, or proof of preventive online adaptation.

Sixteen previously accepted facts are candidates: the original twelve plus wave one. Measure each accepted color's four-option conditional probability using two operational probe phrasings before and after wave two. These probes are disjoint from training and all final evaluation templates. They use the external accepted ledger's values, not the evaluator's world answer key. A wrong accepted ledger would still misdirect this selector. Probe all candidates; record the cost of both passes explicitly.

For each candidate, compute the increase in mean negative log probability, clipped below at zero. Select the four largest losses, breaking ties by subject name. This is a fixed replay-capacity comparison, not a learned threshold or evidence that four is optimal. Both checkpoints are observed before selection. No evaluation output enters ranking, random matching, training scheduling or stopping.

Two GPU arms begin at identical affected weights with fresh AdamW optimizers. Drift replay uses the four selected old facts plus the four latest-wave facts. Random replay uses four old facts sampled without replacement, matched to the drift selection's exact two-template token-length strata, plus those same four latest facts. Random selection may overlap the drift set. Both have identical examples, input tokens, answer tokens, padding and steps. The latest facts are included equally to test repair without losing the recent learning. LR 0.0002, ten replays, batch size four, unchanged NF4 and rank-16 all-linear LoRA. Randomize execution order by seed; verify resets exactly. Baseline is the affected checkpoint with no further training.

Operational probes: "Record the beacon hue registered for {name}." and "For the site named {name}, return its beacon color." The two original evaluation phrasings and four additional phrasings remain separate. They are already known evaluation templates, not a new generalization test. Evaluate all twenty facts without retrieval. Report overall, repaired-target, original-other, wave-one and latest-wave accuracy; old false-answer recurrence; and recovery of facts that the affected checkpoint answered incorrectly. Selection is a confidence-loss policy, so a high rank is not necessarily an incorrect answer. Report actual ranks, buffer overlap and inclusion of errors only after selection.

The random arm's token budget is conditioned on drift selection, so this estimates the content-selection benefit at matched training cost. It does not establish end-to-end speed superiority. Report before/after probe time separately; a deployed random selector would not need these probes or the before-checkpoint reload. Both inference and training cost matter. CPU/CUDA/wall timings are not energy or FLOPs.

Verify frozen source/fixture/checkpoint hashes, before/after checkpoint evaluation reloads, finite losses and probabilities, paired training budgets, and fresh final drift-adapter reload on both evaluation sets. Preserve original checkpoints and both outputs. This tests immediate recovery over fictional four-color facts, not long-term stability, autonomous fact checking, semantic erasure or resident readiness.
