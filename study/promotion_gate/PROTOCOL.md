# Gate candidate weights before adoption

Freeze before new probe outcomes. Reuse baseline and candidate checkpoints from the completed three-seed `drift_replay/` experiment. Baseline is the affected small-buffer wave-two adapter. Candidates are drift-selected replay and token-matched random replay. These known candidates include observed collateral failures, so this is a retrospective engineering validation, not a new independent effectiveness trial. No new training occurs.

Promotion probes are two predeclared phrasings, distinct from all training, drift-selection probes and final evaluation phrasings: "Consult the beacon record for {name}. Which color is listed?" and "For {name}, supply only the recorded beacon color." Probe all twenty accepted facts using the accepted ledger, not the world evaluator. Candidate decisions consume only these probe receipts, not final evaluation output. Expected answers are supplied accepted records, not truths discovered by the gate.

Strict rule: every probe answer that was correct at baseline must remain correct, and at least one previously wrong probe answer must become correct. Otherwise retain the baseline. No demonstrated gain is an unchanged/no-op outcome, not proof of harm. Probabilities are validated for finite range and normalization; mismatched/duplicate probe coverage or changed ledger values fail closed. This rule protects categorical probe correctness, not every confidence margin or every possible phrasing. Discrepancy between promotion probes and final evaluation is a result.

Compare policies using identical saved candidates: always adopt drift; guarded drift (adopt drift only if it passes, otherwise baseline); and guarded fallback (try drift, then random if drift fails, then baseline if neither passes). Also report always-random and unchanged baseline references. Fallback has access to both already-trained candidates, so do not imply equal candidate-generation cost with a one-candidate policy. Rejection can preserve old errors and lower total accuracy relative to an improving but damaging update. Report this utility tradeoff explicitly.

Candidate decisions are written before their final evaluation is computed in this run. Final evaluation reuses the two original and four additional phrasings for the same twenty four-color facts. Validate source checkpoint reloads against preserved receipts, but those metrics do not enter decisions. Once decisions are committed, create an experiment-local active manifest for the guarded fallback using immutable checkpoint hashes; reload that selected adapter and verify final outputs. This constitutes a concrete weight-selection mechanism, not a resident integration or deployment. Baseline pointers preserve rollback; source weights remain untouched.

Primary outcomes: promotion decisions, collateral losses caught and missed on final evaluation, useful gains retained or forgone, and overall/target accuracy. Report each seed and both prompt families. Record promotion inference cost separately from evaluation, loading and already-incurred training costs. Probe all candidate checkpoints for the comparative audit; distinguish that audit cost from sequential deployment cost. There is no claim of energy/FLOP saving, confidence calibration, semantic erasure or indefinite protection. Tests include an unchanged candidate, improvement-only, net improvement with collateral damage, malformed receipts, and immutable activation. No tuning after probe results.
